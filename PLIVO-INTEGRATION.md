# Plivo Integration for Replio

**Replaces SignalWire with Plivo for superior IVR, transcription, and cost efficiency.**

---

## 📋 What Plivo Provides

| Feature | Benefit |
|---------|---------|
| **Inbound Calls** | Receive customer calls, route via AI IVR |
| **Outbound Calls** | Make calls from Replio interface |
| **IVR Routing** | Intelligent call routing via AI agents |
| **Call Recording** | Automatic recording for compliance/training |
| **Real-time Transcription** | Convert speech to text live |
| **SMS/Messages** | Two-way messaging (bonus feature) |
| **Webhooks** | Event-based call handling (call answer, hangup, DTMF) |
| **Cost** | Lower per-minute rates than SignalWire |

## 🚀 Setup: 4 Steps

### Step 1: Create Plivo Account

1. Go to **https://www.plivo.com**
2. Sign up for free account
3. Get your **Auth ID** and **Auth Token** from dashboard
4. Buy a phone number (or rent one): `+1234567890`

**Find credentials:**
- Dashboard → Account → Auth ID & Auth Token
- Dashboard → Phone Numbers → Your number

### Step 2: Add to Railway

In Railway backend service **Variables**:

```
PLIVO_ENABLED=true
PLIVO_AUTH_ID=your-auth-id-here
PLIVO_AUTH_TOKEN=your-auth-token-here
PLIVO_DEFAULT_PHONE=+1234567890
```

Also keep your existing:
```
LOCAL_AI_ENABLED=true
LOCAL_AI_API_KEY=your-key
OPENCLAW_URL=http://YOUR-IP:20000
LLAMA_CPP_URL=http://YOUR-IP:20001
```

### Step 3: Deploy Backend

```bash
cd C:\AI\Clients\DweezyAiTEAM\v_assistant\replio-v2
git add -A
git commit -m "feat: add Plivo integration with AI IVR"
git push origin main
```

Railway auto-redeploys. Monitor logs.

### Step 4: Configure Plivo Webhooks

In Plivo dashboard:

**For Inbound Calls:**
- Answer URL: `https://replio-2-public-production.up.railway.app/plivo/answer`
- Hangup URL: `https://replio-2-public-production.up.railway.app/plivo/hangup`

**For SMS (optional):**
- Webhook URL: `https://replio-2-public-production.up.railway.app/plivo/sms`

## 🎯 How It Works

### Inbound Call Flow

```
Customer calls → Plivo receives → Webhook to /plivo/answer
                                      ↓
                            AI generates greeting
                                      ↓
                            IVR collects digit input
                                      ↓
                    Routes: 1=Scheduling, 2=Support, 3=Billing, 0=Agent
                                      ↓
                    AI processes selection, transfers or collects info
                                      ↓
                    Call ends → Webhook to /plivo/hangup
                                      ↓
                            Recording saved + transcribed
```

### Outbound Call Flow

```
Agent clicks "Call" in Replio
            ↓
POST to /plivo/initiate-call?to_number=+15551234567
            ↓
Plivo dials customer
            ↓
Customer answers → /plivo/answer
            ↓
Call conversation happens
            ↓
Customer hangs up → /plivo/hangup
            ↓
Recording & transcript saved
```

## 🔧 API Endpoints

### Inbound Calls

```bash
# Plivo calls this when customer calls in
POST /plivo/answer?call_uuid=...&from_number=+15551234567&to_number=+14445556666

# Generate IVR menu
POST /plivo/ivr?call_uuid=...&from_number=...

# Handle digit input (1-9, 0)
POST /plivo/ivr-action?call_uuid=...&digits=1

# Call ended
POST /plivo/hangup?call_uuid=...&duration=120
```

### Outbound Calls

```bash
# Initiate call from agent
POST /plivo/initiate-call?to_number=+15551234567&company_id=YOUR-ID
-H "Authorization: Bearer $JWT_TOKEN"

# Check call status
GET /plivo/call-details/{call_uuid}?company_id=YOUR-ID
-H "Authorization: Bearer $JWT_TOKEN"

# Health check
GET /plivo/health
```

## 🤖 AI Integration

Plivo works WITH your hybrid AI setup:

```
Inbound Call
    ↓
Plivo → /plivo/answer endpoint
    ↓
Local AI (OpenClaw) generates greeting
    ↓
GetDigits collects DTMF input
    ↓
/plivo/ivr-action calls Local AI to analyze digit
    ↓
Local AI decides: scheduling? support? billing? agent?
    ↓
Response sent back to Plivo
    ↓
Call routed accordingly
```

**Requirements:**
- OpenClaw on port 20000 (primary)
- llama.cpp on port 20001 (fallback)
- LOCAL_AI_ENABLED=true in Railway

## 🔐 Security

**Plivo webhooks are public-facing but:**
- Auth token required for API calls (railway variables only)
- Conversation company_id validated
- JWT tokens required for outbound/details endpoints
- HTTPS only (Railway provides SSL)

**Best practices:**
1. Keep PLIVO_AUTH_TOKEN in Railway secrets only
2. Never commit credentials to git
3. Validate company_id in webhook handlers
4. Enable call recording for compliance

## 🐛 Troubleshooting

### Calls not routing
```bash
# Check Plivo health
curl https://your-railway-backend/plivo/health

# Check logs for webhook delivery
Plivo dashboard → Logs → Webhooks
```

### IVR not speaking
```bash
# Verify Local AI is running
curl http://localhost:20000/health

# Check if OpenClaw is accessible
curl http://YOUR-IP:20000/health
```

### Recording not saved
```bash
# Plivo may have failed to record
Check /plivo/hangup logs for errors

# Ensure record=True in make_outbound_call
```

### High latency on IVR
```bash
# Local AI response slow?
Check GPU usage on beast machine

# Network latency between Railway and local machine?
Use ngrok tunnel for faster testing
```
